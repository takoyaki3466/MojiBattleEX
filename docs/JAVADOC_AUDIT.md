# 日本語Javadoc監査記録

## 対象

- `core/src/main/java`
- `item/src/main/java`
- `lwjgl3/src/main/java`
- Javaソース: 152ファイル
- 型宣言: 161件（内部型を含む）
- メソッド／コンストラクタ候補: 742件

件数は字句ベースの静的走査結果であり、匿名クラスのメソッドも含む概算である。全ファイルを型・メソッド宣言単位で走査し、既存Javadocの配置と説明対象を確認した。

- lifecycleイベントの同期配送、配送中の購読変更、購読解除
- JSON読込、旧形式の正規化、参照・数値・アセット・翻訳キー検証
- Definitionから状態付きAbilityを生成するruntime Factoryと起動順序
- 戦闘更新順、戦場オブジェクトの遅延追加、範囲攻撃、クールタイム合成
- HP、必殺ポイント、スキルストック、状態効果の更新規則
- カスタムキャラクター保存の検証、一時ファイル、読込失敗時の扱い
- 補助能力の発動条件、専用ゲージ消費、共通演出
- 着弾要求を一度だけ消費する戦闘オブジェクトの契約

## Javadocを省略した判断基準

次の実装は、型のJavadocと識別子だけで契約が明確で、特殊な副作用や例外条件がない場合に限り省略した。

- フィールドをそのまま返すgetter
- 単純な代入だけを行うsetter
- フィールド初期化だけのコンストラクタ
- 新しいインスタンスを返すだけの単純Factory
- 親インターフェースの契約をそのまま実装する`id()`や`expired()`
- Scene2D/libGDXの定型的なライフサイクル委譲

一方、値の消費、コレクション変更、外部ファイルアクセス、凍結、例外、呼出順序、状態共有の有無が重要なメソッドには説明を残した。

## 静的確認

- Javadoc開始・終了記号の件数一致
- Javadocがアノテーションの後へ誤配置されていないこと
- `{@link ...}` の参照先が同一ソースまたはimportに存在すること
- 追加した`@param`名が実引数名と一致すること
- Javaソースのpackageと配置パスの一致
- `core`から`item`実装への逆依存がないこと
- 差分の空白エラー確認

指示に従い、ビルド、コンパイル、テスト、Javadocツール、アプリケーション実行は行っていない。そのため、コンパイラとJavadoc生成器による最終検証は未実施である。
